WHAT WAS BROKEN AND WHAT CHANGED
--------------------------------
v7 (weapons-sync.php) - POST no longer uses INSERT ... ON DUPLICATE KEY UPDATE.
    The weapons table has a UNIQUE index on registry_number, and every record
    with a blank registry number shares the single empty-string slot. The old
    statement therefore rewrote whichever weapon held that slot and still
    answered 201, so a save could report success while the record you edited
    never changed and a different weapon was overwritten. POST now looks the
    row up by id and updates it, inserts only when the id is genuinely new,
    stores a blank registry number as NULL (NULLs do not collide), and answers
    409 instead of silently overwriting on a real registry-number clash.
    PUT/DELETE were already keyed on id and are unchanged.

v5 (weapons.php) - sends Cache-Control: no-store, so neither the browser nor
    the host CDN can replay the arsenal from before the save. The main site's
    Armory Browser also adds a cache-buster of its own.

Console - BUILD 2026-10-19.2 stages the picture when you pick it, sends the
    database an absolute URL (works when embedded, not just on the subdomain),
    and reads the record back after saving: "Image confirmed in database" or
    "IMAGE NOT STORED".
