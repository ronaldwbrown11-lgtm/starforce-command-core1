October 19, 2026 — the "I saved it and the database did not change" fix. The weapons table has a UNIQUE index on registry_number, and every record with a blank registry number shares the one empty-string slot. The old sync used INSERT ... ON DUPLICATE KEY UPDATE, so a save could rewrite a different weapon, answer 201, and leave the record you edited untouched. v7 resolves the row by id first, stores blank registry numbers as NULL, and answers 409 on a real clash instead of overwriting. v5 adds Cache-Control: no-store so the front end cannot replay an arsenal from before the save. Upload both PHP files, keeping the live database password, then hard-refresh the console.

Earlier: images on the front-facing weapon card (the console's picture now persists through the API instead of staying in one browser's localStorage), image downscaling to stay under upload limits, JSON-string tolerance in the card so a partially deployed server still renders.

Console only (BUILD 2026-10-19.2): download this file (it saves as armory-console.html), upload it to the armory.starforcebase1198.com web root without renaming it, then open armory.starforcebase1198.com/armory-console.html. Do not overwrite index.html and do not open the bare subdomain — that URL is the old cached page and is why an upload can look like it did nothing.
